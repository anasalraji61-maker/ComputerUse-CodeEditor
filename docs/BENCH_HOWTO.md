# تشغيل النموذج الحقيقي والقياس (يدوي من المالك)

المفاتيح تُوضع في متغيرات البيئة (أو تُلصق في «الإعدادات» لهذه الجلسة فقط)، ولا تُكتب في أي ملف داخل المستودع.

## تشغيل التطبيق بنموذج حقيقي
الأسهل: زر «الإعدادات» داخل النافذة (انظر `USER_GUIDE.md`). أو من نافذة CMD (المفتاح يبقى لهذه النافذة فقط):

    set ANTHROPIC_API_KEY=ضع_المفتاح_هنا
    set COS_PROVIDER=anthropic
    run_assistant.bat

لـ Gemini: `set GEMINI_API_KEY=...` و`set COS_PROVIDER=gemini`. لـ OpenAI: `set OPENAI_API_KEY=...` و`set COS_PROVIDER=openai`. لـ Ollama المحلي: `set COS_PROVIDER=ollama` (بلا مفتاح). القيمة `auto` تختار المتاح بالترتيب Anthropic ثم Gemini ثم OpenAI، وبلا `COS_PROVIDER` يعمل الوضع المحلي المجاني.
نماذج مخصصة: `COS_SMALL_MODEL` و`COS_LARGE_MODEL`. تنبيه: متغير بيئة صريح (مثل `COS_PROVIDER`) يتقدم على ما حُفظ من «الإعدادات».

## القياس (يستهلك رصيداً فعلياً بسقف حماية)

    py -m bench.run_bench --provider gemini        (أو anthropic / openai / ollama)

شغّله من مجلد المشروع (حيث `run_bench.bat`). المهام الخمس: ترتيب حسب النوع، نسخ مع التحقق من البصمة، إعادة تسمية دفعة، تحديث برنامج (winget محاكى)، إنشاء هيكل مشروع. كل دورة في مجلد مؤقت معزول ولا تمسّ ملفاتك.

الافتراضي **20 دورة لكل مهمة** (بوابة SPEC). قبل أي إنفاق يطبع التقدير (~كلفة المهمة، ~كلفة القياس كله) وسقف الإنفاق (الافتراضي ضعف التقدير، حد أدنى 1$ ويمكن تغييره بـ `--max-usd`) ثم **يطلب تأكيدك** (اكتب `y`)؛ للتشغيل بلا سؤال أضف `--yes`. `--runs 5` لقياس أسرع وأرخص. المفتاح يُطلب بإدخال مخفي مع `--ask-key` ولا يُحفظ (ولا يلزم مع Ollama). افتراضياً يُقاس النموذج وحده؛ أضف `--with-rules` لقياس الوضع المختلط (القواعد المحلية أولاً ثم النموذج). بلا `--yes` وبلا شاشة تفاعلية يرفض البدء ولا ينفق شيئاً.

يطبع التقرير: نسبة النجاح لكل مهمة مع الحد الأدنى لفاصل ويلسون 95% وPASS/FAIL مقابل بوابة SPEC (تقدير نقطي ≥90% بدورات كافية) وقائمة الأعطال، ثم الخطوات والتوكنات والكلفة بالدولار والنقاط. **لا يكتب شيئاً في المستودع** إلا إن أضفت `--write-doc` (فيكتب `docs/MEASUREMENT.md` أو `--out` المحدد) ولا يُنفّذ commit أبداً. يتوقف تلقائياً عند بلوغ السقف. تحديث winget محاكى دائماً؛ لا يتغير أي برنامج على جهازك.

## بنقرتين (الأسهل)
- **القياس:** انقر `run_bench.bat` ← اختر المزوّد (1 = Gemini وهو الافتراضي، 2 = Anthropic، 3 = Ollama المحلي بلا مفتاح وبلا كلفة لكنه أبطأ بكثير؛ لا يوجد OpenAI في هذه الشاشة، له الأمر المباشر أعلاه) ← يسألك: هل تحفظ النتيجة في `docs\MEASUREMENT.md`؟ (الافتراضي لا: تُعرض فقط) ← يطلب المفتاح بإدخال مخفي (لا يُحفظ ولا يُعرض) ← يعرض التقدير والسقف ويطلب تأكيدك (اكتب `y`). إن حفظتها فالمزامنة مع المستودع تتم بعد تشغيل `tools\register_sync.bat` مرة واحدة (وإلا شغّل `tools\sync_repo.bat` يدوياً).
- **ملف exe:** انقر `build_exe.bat` ← ينتج `dist\COS_Assistant.exe` يعمل بنقرتين دون بايثون (يحتاج بايثون والإنترنت مرة واحدة للبناء فقط، ويثبّت PyInstaller تلقائياً؛ يفضّل بايثون 3.14 ثم أي بايثون 3 متوفر، ويجب أن يعمل `tkinter` فيه). أغلق `COS_Assistant.exe` إن كان يعمل قبل البناء. بعد البناء يشغّله البناء نفسه 15 ثانية بمجلد بيانات مؤقت ويقول «passed the smoke test» أو «SMOKE TEST FAILED». لم يُؤكَّد بعد في السجلات أنك بنيته على جهازك؛ إن فشل أرسل الرسائل الظاهرة. قد يحذّر SmartScreen لأن الملف غير موقّع.
- **مجلد العمل:** من الواجهة زر «تغيير المجلد» (مثلاً Downloads). تُرفض مجلدات النظام والبرامج وAppData وجذر القرص والمجلدات الشبكية ومجلد المستخدم الرئيسي نفسه والمجلدات الحساسة.

## القياس بنموذج محلي (Ollama)
`py -m bench.run_bench --provider ollama --runs 3` — بلا مفتاح وبلا كلفة (يطبع «التقدير: 0$»)، بعد `ollama pull qwen2.5:7b` وتشغيل Ollama. يمكن تغيير النموذج بـ `COS_SMALL_MODEL`/`COS_LARGE_MODEL`. أبطأ بكثير من السحابة؛ ابدأ بدورات قليلة (بوابة SPEC تتطلب 20 دورة، ولا تُحسب البوابة محققة بأقل من 3 دورات).
