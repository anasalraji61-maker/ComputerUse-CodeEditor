# تشغيل النموذج الحقيقي والقياس (يدوي من المالك)

المفاتيح تُوضع في متغيرات البيئة فقط، ولا تُكتب في أي ملف داخل المستودع.

## تشغيل التطبيق بنموذج حقيقي
في نافذة CMD (المفتاح يبقى لهذه النافذة فقط):

    set ANTHROPIC_API_KEY=ضع_المفتاح_هنا
    set COS_PROVIDER=anthropic
    run_assistant.bat

لـ Gemini: `set GEMINI_API_KEY=...` و`set COS_PROVIDER=gemini`. القيمة `auto` تختار المتاح.
نماذج مخصصة: `COS_SMALL_MODEL` و`COS_LARGE_MODEL`.

## القياس (يستهلك رصيداً فعلياً بسقف حماية)

    py -m bench.run_bench --provider gemini

الافتراضي **20 دورة لكل مهمة** (بوابة SPEC). قبل أي إنفاق يطبع التقدير (~كلفة المهمة، ~كلفة القياس كله) وسقف الإنفاق (الافتراضي ضعف التقدير، حد أدنى 1$ ويمكن تغييره بـ `--max-usd`) ثم **يطلب تأكيدك** (اكتب `y`)؛ للتشغيل بلا سؤال أضف `--yes`. `--runs 5` لقياس أسرع وأرخص. المفتاح يُطلب بإدخال مخفي مع `--ask-key` ولا يُحفظ.

يكتب `docs/MEASUREMENT.md`: نسبة النجاح لكل مهمة، الخطوات، التوكنات، الكلفة بالدولار والنقاط. يتوقف تلقائياً عند بلوغ السقف. تحديث winget محاكى دائماً؛ لا يتغير أي برنامج على جهازك.

## بنقرتين (الأسهل)
- **القياس:** انقر `run_bench.bat` ← اختر المزوّد (1 = Gemini وهو الافتراضي، 2 = Anthropic) ← يطلب المفتاح بإدخال مخفي (لا يُحفظ ولا يُعرض) ← يعرض التقدير والسقف ويطلب تأكيدك ← يكتب `docs/MEASUREMENT.md` ويتزامن مع المستودع تلقائياً **بعد تشغيل `tools\register_sync.bat` مرة واحدة** (وإلا شغّل `tools\sync_repo.bat` يدوياً).
- **ملف exe:** انقر `build_exe.bat` ← ينتج `dist\COS_Assistant.exe` يعمل بنقرتين دون بايثون (يحتاج بايثون مرة واحدة للبناء فقط). لم يُختبر البناء على ويندوز بعد؛ إن فشل أرسل الرسائل الظاهرة.
- **مجلد العمل:** من الواجهة زر «تغيير المجلد» (مثلاً Downloads). تُرفض مجلدات النظام والبرامج وAppData وجذر القرص والمجلدات الحساسة.
